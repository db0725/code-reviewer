# 工作台前端改版与验证记录

日期：2026-11-11。使用 [frontend-design-direction](https://github.com/affaan-m/ECC/blob/main/skills/frontend-design-direction/SKILL.md)，设计约定见 [UI_DESIGN_CONTRACT.md](../docs/UI_DESIGN_CONTRACT.md)。本轮修改前端，不修改审查引擎、模型协议、预算和验收口径。

## 改了什么

- 删除宣传式标题区、英文口号、无意义编号和装饰箭头，首屏直接呈现代码审查工作区。
- 保留三栏工作流，使用中性表面与蓝色操作反馈，增删和风险状态单独配色。统一排版、间距、边框、焦点和按钮状态，移除旧样式反复覆盖的规则。
- 扩大代码和报告可视区域，桌面代码13px，窄屏12px；页面文字对比度提高，不再依赖8–10px的低对比说明承载重要内容。
- 示例改为紧凑选择列表，预览后自动折叠仓库与版本设置，侧栏优先显示文件；修改提交或说明后重新展开并使旧预览失效。
- 固定版本与文件规模保持可见，详细资源说明按需展开；报告优先呈现警示、摘要、问题与原文，完整候选复核和资源记录仍保留。
- `limited` 显示为“未完成”，避免将复核不确定误写成仅达到调用限制。新增启动中、启动失败和恢复初始状态的文案。
- 补齐文件选中状态、跳到工作区链接、可聚焦代码区域、标签页方向键/Home/End、Tab焦点顺序和减少动态效果规则。
- 移动端单列浏览，增加代码/审查快捷跳转；长代码在局部横向滚动，不压缩整页字号。

## 实际验证

内置浏览器连接返回“browser-client is not trusted”，本轮未更改其信任配置。改用本机已安装Chrome的隔离无头实例，使用独立资料目录，不操作个人浏览器会话。

9项Node页面状态测试通过。实际浏览器中验证：

- 1440×900、1024×768、390×844布局，初始页面无整体横向溢出。
- 真实本地服务的缺陷示例离线回放、完成报告、证据跳转、高亮及Markdown附件响应。
- 正常重构示例的真实离线回放，零告警时仍明确显示回放和静态范围。
- DKNet本地真实提交读取与预览、预览后折叠设置、资源设置展开与文件列表；没有启动模型审查。
- 无效仓库路径触发真实本地错误，缺少模型密钥通过测试页受控响应模拟，未改变服务密钥。
- 不完整批次、待核实候选通过受控结果模拟，页面不出现绿色“未发现问题”结论。
- 手机视口报告阅读，以及受控长文件名和长中文说明，均无整体横向溢出。
- 实际键盘方向键切换标签页、Tab从真实审查按钮到回放按钮；焦点轮廓2px，减少动态效果时过渡为0s。
- 初始手机场景和展开的仓库表单中，可见控件均有可识别标签；抽查集合的正文/代码颜色对比度均至少4.5:1，记录最低值分别5.16与4.56。

对比度检查基于当前场景中选定文本元素的计算样式，没有覆盖所有潜在内容与组合，不等于完整WCAG认证。未使用屏幕阅读器或真实手机硬件。受控显示状态不代表真实模型执行结果。**本轮真实模型调用为0。**

## 检查发现的问题与修复

1. 初版增删行号使用的灰色在增删背景上只有约4.14–4.15:1，未达到本轮正文检查门槛。加深行号后复查通过，保留真实行号和差异标记。
2. 新增启动失败文案后，`resetReview()`最初只重置可见性，没有重置空状态内容，导致切换示例或预览仓库后仍显示上一次失败/启动文案。补充统一重置，并在Node与浏览器检查中断言恢复“尚未开始审查”。
3. 仓库预览时版本表单挤占文件列表；改为预览成功后收起设置，编辑版本时重新展开。最终截图确认能同时浏览更多文件。

## 第二次调整：把阅读空间交还给使用者

用户反馈：本地仓库的说明和快照信息依然占用编辑器上部，面板不能拖动，代码窗口仍然太小。第一轮只收紧视觉，没有充分解决真实阅读需求。

补充设计见 [代码阅读布局约定](../docs/UI_READING_LAYOUT_CONTRACT.md)。本轮实现：

- 仓库说明默认收起，通过编辑器标题旁“展开说明”查看；内置示例保留说明，分别记住两种来源的选择。
- 顶部“文件栏”“审查栏”可以隐藏或恢复两侧；两条分隔线支持拖动宽度，代码区至少保留280px。
- 底边“拖动调整高度”支持工作区整体增高或缩短；分隔线可以键盘微调、双击恢复默认。
- “专注代码”临时隐藏两侧与说明，点击退出或Escape恢复原布局；“重置布局”恢复全部默认尺寸。
- 尺寸、面板显示和说明偏好只保存在本机，刷新会恢复；视口变窄会重新限制尺寸，手机隐藏不适用的拖动柄。
- 首次选择仓库优先打开非空的变更Python文件，避免停留在README或空的初始化文件。

同一DKNet预览、1440×900、同一份代码：说明展开时代码容器340.45px高，收起后544.41px高；专注模式从722px宽增至1406px宽。拖动高度增加70px后，代码容器约614.41px高。这是布局测量，不是模型性能指标。

本轮9项Node状态检查通过。独立Chrome中实际发送指针拖动、键盘和刷新事件，检查了双侧宽度、整体高度、隐藏恢复、专注/Escape、键盘微调、本机存储恢复、1024视口的最小代码宽度保护与手机专注模式；原来的回放、证据跳转、下载、资源设置、错误与部分完成检查也通过。真实模型调用为0。

材料单独保存于 `tests/results/ui-reading-layout-20261111/`，没有覆盖第一次记录。新增关键截图为 `git-preview.png`（默认收起）、`git-expanded.png`、`git-resized.png`、`git-focus.png`、`laptop-resized.png`、`mobile-focus.png`；完整观测位于 `interaction-checks.json` 的 `layoutChecks`。`evidence.json`记录本轮验收材料。

测试最初在改变视口后立即定位拖动柄，可能赶在响应式回调完成前点到正文并产生文本选择。已改为等待两帧渲染稳定，且必须断言拖动柄实际捕获指针及预期宽度发生变化，避免把“没有溢出”误当成“拖动成功”。
