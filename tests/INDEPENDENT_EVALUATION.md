# 新增独立合成评测说明

## 数据来源与“独立”的含义

本轮新增12个人工合成案例，不复用原来的三个内置示例或DKNet固定补丁，也不表示真实仓库存在这些缺陷。每个案例包含修改前后代码、公开契约、一个待检验候选，以及仅评测端可见的预期与行为验收。

这些案例由项目开发者侧构造，并非外部第三方盲测集。“独立”指它们与既有开发案例分开，且保留组不用于观察结果后调参；不代表无构造偏差或可泛化到任意仓库。

| 分组 | 案例 | 主题 | 用途 |
| --- | --- | --- | --- |
| 开发组 | IE001–IE004，2缺陷/2正常 | 跨调用状态更新、装饰器异常保护 | 实现及校准证据包与复核格式 |
| 保留组 | IE005–IE012，4缺陷/4正常 | 单位转换、到期边界、幂等标记、异常资源释放 | 冻结后首次观察效果 |

每个主题包含一个有缺陷改动和一个正常改动。模型端不接收开发/保留划分、答案、验收函数或冻结清单。

## 独立验收与冻结

`independent_oracles.py` 只执行本项目新建的可信微型夹具，检查具体输入下的功能契约；不接受外部仓库代码或模型生成代码。修改前应通过；缺陷修改后应违反指定契约；正常改动后应保持契约。

`independent-freeze.json` 固定案例序列、公开输入构造器及验收代码SHA-256，真实评测前检查一致性。冻结记录在真实观察之前生成；运行结果还保存模型标识、运行代码摘要、调用预算及条件顺序。原始结果不覆盖。

开发组可以用于定位缺口；它的成绩不能当成保留组成绩。观察保留组之后，该组也成为已观察数据，后续调参应增加新的保留组，不能反复挑最好的一次。

## 两种评测必须分开看

### A. 给定候选的复核判别

同一个候选分别提供两类证据：

- `anchor-only`：候选附近及其原引用代码，保留同样的公开任务背景。
- `call-and-state`：增加调用目标、状态副作用、装饰器、旧版行为和调用方等线索。

两种条件使用同样的复核提示、Schema和一次请求机会，顺序按案例ID的固定哈希交错，不根据结果挑顺序。模型只看对应证据包；私有预期在返回后才用于评分。

这些候选刻意覆盖跨文件反证，条件之间可见信息量不同，因此结论只适用于这组构造任务。模型随机性、服务端版本和缓存影响并未完全消除。

### B. 端到端发现与复核

只给修改前后代码和公开描述，让发现阶段自主提出候选，再复核它实际提出的候选。预先构造的候选不进入发现模型。

保留原候选数量、复核保留数量、待核实数量、完成状态与所有原文。默认只列出这些统计，报告语义仍需结合独立验收逐项复核，不能把位置命中直接当作正确缺陷。

## 指标口径

对给定候选，行为验收对应的预期是 `supported` 或 `refuted`；模型也可以选择 `uncertain`。

| 指标 | 定义 |
| --- | --- |
| 判别覆盖率 | 实际作出支持/反驳的案例数 ÷ 计划案例数 |
| 已判别正确率 | 正确支持/反驳数 ÷ 作出支持/反驳数；未判别时为未知 |
| 全部案例匹配率 | 正确支持/反驳数 ÷ 计划案例数 |
| 错误支持 | 预期应反驳，却判为支持 |
| 错误反驳 | 预期应支持，却判为反驳 |

不确定、结构或证据不合法、接口失败和预算下未执行分别列出。不能只展示已判别正确率而隐藏覆盖率，也不能将复核判别指标称为端到端缺陷发现准确率。样本量很小，不支持生产效果承诺。

## 命令与预算

在主项目目录运行：

```powershell
.\.venv\Scripts\python.exe -m tests.evaluate_independent --split dev --mode verifier --output tests/results/new-dev-evaluation
.\.venv\Scripts\python.exe -m tests.evaluate_independent --split holdout --mode both --output tests/results/new-holdout-evaluation
```

会调用真实模型。输出目录必须是新目录。`--mode verifier`只比较给定候选；`--mode end-to-end`只运行发现与复核；`both`执行两者。

评测套件默认总保护为40次请求、600秒、300,000输入token预检。它运行多个小案例，与网页单次仓库任务的50次、300秒不是同一层预算。端到端单案例另限制为最多6次调用、90秒，且受套件剩余预算约束。

退出码0表示计划的流程已执行，不表示模型全部答对。中断、未执行或端到端存在未核实范围会保留记录并以非零状态结束，不自动重新运行直到出现更好结果。
