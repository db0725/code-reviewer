# 候选复核与新增独立评测结果

本轮于2026-11-02启动，保留组于北京时间2026-11-03完成。实现了候选复核与新建合成评测，没有覆盖此前结果，也没有修改FunASR或DKNet。

## 1. 已接入的功能

仓库默认流程为：发现候选 → 生成调用与旧版证据包 → 严格复核 → 分类展示。

复核分别检查故障机制、变更引入性、具体影响。整体支持需要三项都获得支持；反驳需要明确的关键反证；证据不足、校验失败、接口或预算问题保留待核实。模型支持是静态意见，不是运行证明。

证据包使用候选原文、同包附近调用定义、状态副作用、装饰器、旧版所在函数及旧版被调用函数。每条引用要真实存在，并完整出现在该次证据包内。它不执行外部仓库代码，也不宣称解决全部动态分派。

发现与复核共用原来的50次调用、300秒总上限及600,000输入预算预检。复核默认最多3个候选、每个最多2次尝试，未处理候选不会丢弃。结构、证据包和所有结论均可回看。

## 2. 新增数据与验收

- 新增12个可信微型合成案例，不复用三个内置示例或DKNet原20个补丁。
- 4个开发案例用于实现与校准；8个保留案例在结果观察前冻结。
- 每个主题包含一个功能缺陷与一个正常改动，覆盖状态副作用、装饰器、单位、到期边界、幂等和异常清理。
- 独立行为验收确认修改前通过、缺陷版本违反指定契约、正常版本保持契约。
- 案例、公开输入构造器与验收代码有SHA-256冻结；模型不接收标签或验收代码。

这是项目侧新建的小型人工合成集，不是外部第三方盲测数据。观察本次保留组后，它已成为已观察数据，后续调参应使用新的保留案例。

## 3. 保留组：给定候选的复核判别

两种条件使用同一个候选、同样的提示和Schema，均只给一次请求机会；顺序按案例ID固定哈希交错，未按结果选择。

| 指标 | 局部证据 anchor-only | 调用与状态证据 call-and-state |
| --- | --- | --- |
| 计划候选 | 8 | 8 |
| 合法结论 | 6 | 8 |
| 明确支持/反驳 | 2 | 8 |
| 正确判别 | 2 | 8 |
| 不确定 | 4 | 0 |
| 校验失败 | 2 | 0 |
| 未执行 | 0 | 0 |
| 错误支持 / 错误反驳 | 0 / 0 | 0 / 0 |
| 判别覆盖率 | 2/8 | 8/8 |
| 已判别正确率 | 2/2 | 8/8 |
| 全部案例匹配率 | 2/8 | 8/8 |
| 已返回输入token | 11,043 | 13,570 |

增强证据条件在这8例上全部匹配预期，多用了约22.9%输入。局部条件没有作出的判断和被主机拒绝的结论都保留在分母与记录中。两种条件的已判别正确率都为100%，不能隐藏覆盖率后声称它们一样有效，也不能把增强条件的8/8写成通用审查准确率。

局部条件的两次失败发生在IE005和IE009：模型给出了整体支持，但必要的机制、引入性或影响判断并非全部支持，被一致性检查拒绝。没有截取输出、放宽规则或按更好结果重跑。

该组刻意构造了需要跨调用证据的候选，信息量不同是实验条件的一部分。结果不能代表所有任务，模型随机性、缓存与供应商版本影响也未被完全消除。

## 4. 保留组：端到端发现与复核

发现模型只接收代码与公开描述，不接收预先构造的候选。它实际生成的候选才进入复核。

| IE006 | 秒转毫秒 | 正常重构 | 0 | 0 | 是 |
| IE007 | 到期等号边界 | 缺陷 | 1 | 1 | 是 |

代码助手对4条保留意见逐项核对：返回秒而非毫秒、恰好到期仍返回缓存、未记录已处理key、异常后open未复位，均与冻结夹具的指定行为验收相符。该静态核对尚未经项目开发者确认，不是仅凭文件或行号命中计分。

4个正常改动没有生成原候选，因此这组端到端试验没有展示“复核把原始误报减少了多少”的收益。不能把给定错误候选被反驳的结果，直接套成端到端误报率下降。

端到端部分22次请求，与16次给定候选对照合计38次真实请求；已返回输入69,599 token、输出12,835 token，缓存命中52,224、未命中17,375。全部用量已返回。原命令因基线两次不合法结论以非零状态结束，未掩盖为全套零错误。

## 5. 历史FunASR候选：仍然保留不确定性

仅复核上一轮已保存的候选，没有重新发现或重审整个仓库。

第一版复核取到了发送函数更新首包标志的反证，却仍因为部分状态字段不同而整体支持原候选。这是一条明确保留的开发回归失败：找到反证不代表模型会正确使用反证。

随后改进同包定义优先级，并把机制、变更引入性、影响分开判断，禁止只支持局部事实却支持整个候选。第二次复核返回：

```text
整体：uncertain
故障机制：unknown
变更引入性：supported
具体影响：unknown
```

它不再作为支持的问题发布，而是保留待核实。**这不是自动证明原候选完全错误。** 返回解释仍需开发者检查；没有执行ASR、音频或训练，也没有给这个真实仓库案例计入独立合成集成绩。

两次分别使用1次请求，输入12,791和13,182 token；原始错误支持与后续不确定结果分别存放，未覆盖或拼接最佳输出。

## 6. 开发过程中的失败也保留

- 开发首轮：增强证据3/4正确判别，1例不确定。原因是新版删除调用后，没有取回旧版被调用函数，无法判断回归归因。
- 补充旧版取证后的开发试验：增强证据3/4正确判别，1例因支持证据数组超过本地长度限制被拒绝。远端Schema子集不涵盖全部本地长度限制，后续明确了提示约束，生产复核保留有限纠错机会。
- 历史FunASR首次复核：发现反证却仍支持原复合主张，推动新增必要判断及一致性检查。
- 最终保留组使用之后未据其结果调参或重跑。

开发与历史回归共18次请求，输入49,265 token；加上保留组，本轮共56次请求、118,864已返回输入token、22,731输出token。这些是多个受限试验的合计，不是单次仓库任务突破50次上限。

## 7. 自动检查与交付限制

110项Python与9项Node状态检查通过。包含复核专用严格函数调用、来源版本与完整原文验证、未知状态、共享预算、原候选保留、旧调用取证、冻结校验、私有标签隔离，以及不确定/失败不被隐藏的指标计算。

本轮不宣称完成浏览器视觉验收，不宣称任务持久化或生产部署。没有修改或重新运行原独立DKNet基准仓库。新的保留组结果只支持该小型合成集合上的开发判断，不支持生产准确率承诺。
