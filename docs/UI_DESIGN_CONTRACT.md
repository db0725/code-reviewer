# 审查工作台界面改版约定

日期：2026-11-11。设计依据：本项目现有页面、代码审查流程与已实现的任务状态；使用 frontend-design-direction。保持原生 HTML/CSS/JavaScript，不增加前端依赖。

## 产品与任务

面向需要反复阅读 Git 变更、核对候选问题与代码证据的开发者。主要动作是选择输入、预览变更、开始审查、阅读意见并定位原文。页面以工具操作为首屏，不承担产品宣传。

## 从现有页面观察到的问题

- 大段宣传页头、英文口号及编号占据代码区域上方空间；删减这些内容，顶部只保留产品名、页面标题和必要范围说明。
- 代码与报告区域固定高度偏小，8–12px 辅助文字和低对比灰绿难以长时间阅读；扩大工作区，正文以13–14px为主、代码13px，保持可读对比。
- 示例被表现为多张装饰卡片，仓库和资源配置又增加嵌套容器；改用紧凑选择列表、表单和分隔线表达关系。
- 复核、报告和资源声明视觉权重接近；优先展示结果摘要和未完成警示，细节按需展开，保留全部范围说明。
- 移动端会把字号缩小以塞入多列；改为单列阅读，保持按钮和正文可读，代码在自身容器内横向滚动。

## 设计方向与检查条件

采用安静、明确的开发工具布局：浅灰导航、白色阅读区、蓝色操作和定位反馈；绿/红表达增删与结果，琥珀表达未完成。保留现有三栏逻辑，桌面代码区为视觉中心，报告区宽度足以阅读中文解释。

- 目标视口：1440x900、1024x768、390x844。
- 桌面主工作区在紧凑页头下立即可见，代码区有足够高度；窄屏按选择、代码、结果顺序排列。
- 页面不出现宣传英雄区、无意义编号、卡片套卡片或装饰渐变。
- 真实模式与回放标记明确；原有接口、模型预算、候选复核和报告语义不变。
- 所有操作可用键盘；可见焦点、显式标签、选中状态和标签页键盘切换；颜色不是唯一的状态提示。
- 长文件名、路径、中文说明和证据不使页面整体横向溢出；代码可局部滚动，位置跳转不丢失结果。
- 有减少动态效果的媒体规则；交互反馈不使用反复装饰动画。
- 成功、失败和未完成结果可以区分，下载和原文定位仍可用。

## 状态约定

| 状态 | 触发 | 可见反馈 | 后续动作 |
| --- | --- | --- | --- |
| 加载 | 初始请求、仓库读取、预览或任务运行 | 明确加载文案，锁定冲突操作，保留布局；任务事件逐条显示 | 等待完成；当前不新增未实现的取消功能 |
| 空内容 | 未选择仓库、尚无报告、完整审查无支持项 | 分别说明需要预览、尚未审查或当前范围无支持项 | 预览/开始审查/查看范围 |
| 错误 | 路径无效、接口失败 | 页面告警和触发操作附近的错误原因 | 修改路径或恢复服务后重新发起 |
| 部分完成 | 批次未完成、超时或复核不确定 | “未完成”与未完成范围，保留已交付意见 | 查看证据、记录或下载报告 |
| 成功 | 任务交付 | 明确完成状态、问题计数与可定位证据 | 阅读、定位、下载 |
| 权限/配置边界 | 真实模式缺少密钥或接口拒绝 | 说明服务端配置问题，不索取或在网页显示密钥 | 配置服务后重试，内置示例可显式选择回放 |

## 验证记录方式

使用独立的本机无头 Chrome 实例验证，隔离浏览器资料目录，不使用个人浏览器会话。内置浏览器连接失败已记录，独立实例不绕过其信任机制。

截图、DOM观测、交互结果和 skill 要求的证据 JSON 放在 tests/results/ui-redesign-20261111/。真实回放用于验证服务与页面；配置失败、部分结果等受控界面场景明确标为模拟，不作为模型能力实测。全部检查不调用真实模型。
