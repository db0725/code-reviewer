# 项目说明与资源缺失机制

2026-10-25。适用于本地 Git 网页审查与 `review_git.py`；内置示例保持原演示方式。

## 网页怎么用

1. 切换「本地仓库」，读取仓库并选择版本。
2. 展开「项目说明与资源设置」，填写说明，例如：数据集与训练权重不随仓库提供，只检查代码。
3. 分别选择数据集、模型权重的状态：未说明、未提供、已提供。
4. 如需额外排除文件，在排除路径中每行填写一条，例如 `private/`、`outputs/`、`cache/*.txt`。
5. 预览代码变更，确认范围后开始真实审查。执行轨迹、结果和下载报告都会保留范围信息。

状态是使用者的声明。选择「已提供」也不会读取图片、加载权重或执行训练。项目说明是背景信息，不作为缺陷已经成立的证据。

预览固定提交、说明和排除规则。修改设置后必须重新预览，开始任务只使用原预览快照；刷新任务恢复原设置，避免展示的说明和实际输入不一致。重启服务后任务记录清空，需事先下载报告。

## 读取和跳过规则

审查工具只读提交快照中的代码，不从 CSV 解析路径后访问本机图片，不下载外部资源。未提交的数据不会进入快照。现有数据集、图片、权重排除策略继续生效；`data/loader.py` 等 Python 代码仍可审查，除非显式排除。

额外排除规则在读取 Git 文件内容、计算加载预算之前执行，对两个版本都生效。说明最多 2,000 字符，规则最多 20 条，每条最多 200 字符。规则使用仓库相对路径：支持精确路径、目录前缀与 `fnmatchcase` 通配符；区分大小写，不是完整的 `.gitignore` 语法。不支持绝对路径、上级目录和 `!` 反向规则。Windows 反斜杠会转换成 `/`。

| 情况 | 工具处理 |
| --- | --- |
| 声明某类数据或权重未提供 | 返回按声明跳过，不读取资源 |
| 声明已提供或状态未知，但请求图片、权重等 | 返回静态审查不读取；不推断资源缺失 |
| 命中用户规则或原有排除范围 | 返回排除原因 |
| 请求的普通代码文件不在当前快照 | 检查快照一次并记录；不检查其他本地位置 |
| 越界路径或非法版本 | 返回工具错误，不把越界请求当作合法资源跳过 |

跳过结果包含版本、路径、类别、原因和重复请求数，并以独立事件显示。相同「版本＋路径」再次请求时直接返回缓存记录，不重新查找。单个路径未找到不会修改整个数据集的状态。

模型被要求收到跳过结果后继续分析代码。宿主另有保护：连续第三次相同工具请求会停止；同一不可用资源即使穿插其他操作，第三次请求也会停止并保留记录。默认受 50 次模型调用、300 秒总时限约束。达到限制属于审查未完成，不能解释成没有问题。

数据集未提供本身不应成为缺陷；数据处理代码中有证据的索引、返回值或缺失文件处理错误仍可报告。提示词无法保证模型判断永远正确，最终意见仍需复核。报告始终标记数据集和权重「未验证」，没有资源错误记录也不表示已经验证成功。

## 命令行与接口

命令行复用相同策略，例如：

```powershell
.\.venv\Scripts\python.exe review_git.py --repo "..\DKNet" --initial --head HEAD --notes "数据与权重需自行准备，只审查代码" --dataset-status not_provided --weights-status not_provided --exclude "data/" --output "tests/results/local-review-results/my-new-run"
```

`POST /api/git/preview` 可增加 `project_context` 字段，旧请求仍兼容：

```json
{
  "notes": "数据集未随仓库提供",
  "dataset": "not_provided",
  "weights": "unknown",
  "excluded_paths": ["private/", "outputs/"]
}
```

这是该字段的内容，不是完整预览请求；完整请求还需 `repository`、`head`、`base`。状态值为 `provided`、`not_provided`、`unknown`。模型配置与密钥仍只在服务端。说明中的已知服务密钥会脱敏，界面使用文本渲染。

实现位置：`resource_policy.py` 负责输入约束、分类与报告；`git_input.py` 负责加载前排除；`review.py` 负责模型约束、跳过缓存与退出；网页及命令行使用同一规则。
